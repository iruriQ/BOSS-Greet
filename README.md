# BOSS Greet & Apply

BOSS 智能招呼与投递助手。

根据 **用户自己的真实经历** 和 **每个岗位的招聘要求（JD）** 生成不同的打招呼用语，逐条校对后发送。公开版本不内置任何人的简历、工作年限、家庭位置、AI 服务地址或密钥。

当前版本：`0.6.1`。BOSS 支持定制招呼语与距家筛选；猎聘、智联招聘、前程无忧和实习僧保留 fork 的投递适配。

## 安装

1. 在浏览器中安装 Tampermonkey（篡改猴）。
2. 下载本仓库的 `boss-auto-apply.user.js`，在篡改猴中导入；或新建脚本，用该文件的完整内容替换后保存。
3. 登录招聘网站，打开职位列表。左下角会出现「定制招呼助手」。

本版与上游脚本、私人构建使用不同名称和存储空间，分别保存配置和记录。旧版用户原有记录不会自动迁入通用版；继续使用已有记录时应更新对应的私人构建。不同版本的去重记录不共用，投递时只运行所需的一份。

支持的页面示例：

- BOSS：`https://www.zhipin.com/web/geek/jobs`、`/web/geek/job`、`/web/geek/job-recommend`
- 猎聘：`https://www.liepin.com/zhaopin/`
- 智联招聘：`https://www.zhaopin.com/jobs/`、`https://sou.zhaopin.com/`
- 前程无忧：`https://we.51job.com/pc/search`
- 实习僧：`https://www.shixiseng.com/interns`

上游 Greasy Fork 页面提供的是上游版本，不包含本仓库的新增功能。

## 第一次使用需要填写什么

打开 BOSS 职位列表，在面板中填写以下内容。修改会自动保存。

| 设置 | 怎么填写 |
| --- | --- |
| 我的简介 | 用一句话介绍自己，可以留空 |
| 工作年限 | 填写真实年限；填写后每条话术都保留，可以留空 |
| 真实经历 | 每行一项，写成能直接发给招聘者的完整句子，包含真实技能、职责或成绩 |
| 开场问候 | 选择「您好」或「你好」 |
| 每条补充 AI 提效亮点 | 可选，默认关闭；开启后只补充本人经历中实际填写的 AI 实践，不编造 |
| AI 接口地址、模型 | 使用自己的、兼容 Chat Completions 的服务；填写完整接口地址及模型名称 |
| 设置本次 API Key | 点击按钮，在弹窗中输入自己的密钥；页面刷新后需重填 |
| 距家筛选 | 可选；先设置家庭起点，再填写最多接受多少公里 |

**想找什么岗位，先在招聘网站中搜索和筛选。** 工具处理当前列表，不限制为商务、运营、数据或 PM。技术、设计等其他方向也可以填写自己的经历使用。

填写经历时，可以采用「使用什么工具，完成什么工作，取得什么结果」的句式。只写本人做过的事，不需要照抄示例。没有 AI 实践经历也可以正常使用。

### 开始投递

1. 填好真实经历及 AI 服务。
2. 点击「预览首个岗位话术」查看一条示例，不会发给招聘者。未配置 AI 服务时，可以根据本地关键词展示标明“未校对”的草稿。
3. 点击「开始」后，按「读取招聘要求 → 选择相关经历 → 生成话术 → 校对 → 发送」执行。勾选「仅预览，不发送」则只生成预览。

默认启用 AI 选择相关经历，适合不同岗位方向。关闭「使用 AI 选择经历」后，改用本地主题、中文短语及英文技能匹配；本地匹配不等于完整语义理解。无论采用哪种匹配，**实际发送前都需要 AI 校对**。

「每条补充 AI 提效亮点」关闭时，AI 实践和其他经历一样按相关性参与选择，不强制追加；开启时额外保留一条已填写的 AI 实践，仍须通过岗位相关性校对。

每条话术最多选取 3 条相关经历，可额外补充 1 条 AI 实践；保留完整句子，不截断成绩或限定条件。默认上限 360 字，可调整到 180—500 字。

## 距家筛选

默认关闭，初始距离上限为 10 公里，可调整为 0.1—200 公里。

1. 在岗位列表先打开一个岗位，点击面板的「设置/修改家庭位置」。
2. 在 BOSS 原生路线规划左侧搜索家庭附近地标，点击候选结果。
3. 点击「同步当前起点为家庭位置」，返回岗位列表，刷新家庭位置并开启距离筛选。

网页不能直接读取 App 保存的家庭地址，需要首次手动选择相同起点。同步后在本机保存。筛选使用直线距离，包含上限边界；不是通勤时间或路线里程。工作地址坐标无法确认时跳过该岗位。家庭位置不会发送给 AI 服务。

## 校对、发送和停止

- 校对包含错别字、语序、用词、事实一致性及岗位相关性。允许有限的语言修正，修改后再次复核；不允许新增资历、改动业绩或扩大职责。
- 单条内容未通过校对时跳过该岗位，继续下一个。接口异常、验证码、平台限制、会话身份不符或发送结果不明时停止，并显示原因。
- 只有确认最终消息已投递才计为成功。即时回执缺失时，可只读核对同一会话的服务器历史；不重复点击发送。
- 「核查未确认发送（只读）」用于检查已有记录，不会重新发送。旧记录缺少完整待核查文本时，不自动改成成功或清除。
- 「检查/加载更多（不投递）」只测试下一批岗位加载。只有平台明确表示无更多且状态稳定时，才报告列表结束；加载超时会说明原因。
- 默认自动翻页，跳过已处理记录和猎头，只处理两周内活跃的 BOSS。投递间隔 4—10 秒、翻页间隔 3 秒、本机每日上限 150 次。这些属于运行限制，平台可能有更低限额，不保证账号不会受到平台限制。

BOSS 平台自身开启默认招呼时，可能先发默认内容，再发本工具的专属话术。需要仅发送专属话术时，请自行关闭平台默认招呼。

猎聘沿用原有沟通流程，必要时发送用户配置的「猎聘招呼语」；智联招聘、前程无忧和实习僧沿用 fork 的申请流程。实习僧保留在线/附件简历、到岗时间、实习时长与每周出勤设置，并为一轮投递复用投递窗口。BOSS 的定制话术和距家筛选仅用于 BOSS。

## 资料保存在哪里

- 简介、经历、偏好、家庭起点及投递记录保存在用户浏览器的脚本存储中；不自动写回本仓库。
- API Key 只保留在当前页面的脚本内存，不保存到配置、日志或构建文件，刷新后失效。
- JD、候选经历与待校对话术会发送到用户自己配置的模型服务。AI 选择经历时会发送参与选择的经历；校对时发送已选中的经历。模型校对可能遗漏语言问题。
- 模型服务默认要求 HTTPS，本机服务允许 HTTP。脚本声明 `@connect *`，供用户自行指定模型服务，实际目标取自用户配置。
- 如需提交 Issue，请只附脱敏截图和复现步骤，不附简历、地址、密钥或私人构建文件。

## 开发与检查

需要 Node.js。执行：

```bash
npm ci
npm run check
npm test
npm run test:browser
npm run check:public
```

`npm run docs:screenshots` 用虚构数据重新生成上面的两张截图；使用实际脚本面板，全部请求均被本机模拟拦截。

`npm run check` 重新生成公开安装文件并检查语法。模拟浏览器测试使用独立浏览器，拦截全部请求，不使用真实账号或真实模型服务；可用 `CHROME_PATH` 指定 Chrome 可执行文件。

`npm run check:public` 检查 Git 会收录的文件，识别误加入的私人文件和疑似密钥；本机存在私人资料时，也比对已知履历和服务地址，不输出具体命中内容。它不能保证发现所有形式的私人信息，提交前仍需查看实际改动。不要直接上传整个项目目录压缩包，私人文件也可能在目录内。

主要文件：

- `src/`：功能源码，修改后重新构建。
- `boss-auto-apply.user.js`：可公开发布的安装文件，默认个人资料为空。
- `candidate.example.json`：空白配置模板，不含密钥。
- `tests/`：虚构测试数据及自动验证。

### 可选：仅在本机预填个人资料

普通用户直接在面板填写即可，不需要执行此步骤。

开发者可复制 `candidate.example.json` 为 `candidate.private.json`，填写 `intro`（简介）、`experience`（年限）、`profile`（用换行分隔的真实经历）和可选的 `service.endpoint`、`service.model`。**不要把 API Key 写入文件**。若使用明确授权的远程 HTTP 服务，可在 `service.httpOrigin` 填写精确 origin（协议、主机和端口）；此例外仅允许该 origin，面板会显示明文传输提示。

```bash
npm run build:personal
```

私人产物位于 `dist-private/boss-auto-apply-personal.user.js`，保留既有私人构建的安装身份和存储键，与通用版分开。私人构建默认保留额外 AI 亮点、采用本地匹配，已保存的面板偏好优先。`candidate.private.json` 和整个 `dist-private/` 均被 Git 忽略，只在本机使用。普通 `npm run build` 不读取私人文件。
